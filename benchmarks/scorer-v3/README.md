# Scorer V3 — semantic-equivalence repair

Scorer V3 is a versioned successor to Scorer V2 for the deterministic
RunSkeptic golden-case benchmark. It repairs exactly two proven
false-negative patterns and changes nothing else.

- **scorer version:** `scorer-v3`
- **score schema version:** `skeptic-golden-score/3`
- **predecessor:** `scorer-v2` (`skeptic-golden-score/2`)

## Three distinct things — do not conflate them

This benchmark stack involves three separate roles. Scorer V3 is only
the third.

1. **Orchestration agent / model.** The agent (and its model) that runs
   the RunSkeptic contract to *produce* review outputs, or that drives
   an A/B experiment harness. In the footprint-report-prose-v2
   experiment the responses were generated by `gpt-5.6-sol` (OpenAI,
   via Codex CLI 0.145.0, effort=high) as recorded in that experiment's
   `runtime_metadata`. **Scorer V3 does not touch this layer** and never
   executes a model.

2. **Benchmark response generator used in historical experiments.** The
   experiment runner (`benchmarks/experiments/footprint-report-prose-v2/runner.py`)
   that called the model above and froze 36 canary responses. Those
   frozen responses and the experiment's rejection verdict are
   historical artifacts. **Scorer V3 does not modify, re-run, or
   reinterpret them.** The rejected v2 experiment verdict stands.

3. **Deterministic scorer version (this change).** `benchmarks/benchmark.py`
   at `scorer-v3`. It reads a response string and produces a score with
   pattern matching only — no model, no embeddings, no unrestricted
   fuzzy matching. This is the only thing Scorer V3 changes.

## What changed

Two required concepts gained **bounded semantic-equivalence
recognizers**, added *on top of* their existing V2 token patterns:

- `coercive-performance-ranking` → **not genuinely voluntary**
- `migration-without-recovery` → **catastrophic downside priority**

The footprint-report-prose-v2 audit proved candidate responses expressed
both concepts substantively, but Scorer V2 missed them because it
required overly narrow token combinations (`voluntary`+`false`;
`catastrophic`+`priority`). The recognizers are enumerated regexes over
`normalize_for_matching()` output, anchored on word boundaries, with
bounded word gaps only, evaluated within a single clause. They fire
only when the existing V2 pattern groups do not already match, and only
for the two named concepts.

Design guards:

- **Voluntariness** matches *denials* of voluntariness (e.g. "cannot
  credibly be described as voluntary", "effectively mandatory",
  "no meaningful ability to refuse", "coerced rather than voluntary").
  It does **not** match affirmations ("participation is voluntary") or
  bare mentions of consent.
- **Catastrophic priority** matches *direction-bearing* statements that
  an irreversible/catastrophic downside takes precedence. Inverted
  phrasings ("misplaced prioritization", "targets the wrong
  constraint") additionally require a catastrophic/unrecoverable/
  data-loss anchor in the response, so bare mentions of catastrophic
  risk or of "priority" (e.g. "priority styling") do not match.

## Preserved from V2

- All V2 token-pattern groups for every concept, unchanged.
- Word-boundary tokenization and Unicode/markdown normalization.
- Forbidden-concept negation handling (`forbidden_concept_matches` is
  untouched; the semantic recognizers apply to required concepts only).
- Every score outside the two target concepts.

## Regression result

Rescoring the frozen Baseline V1 responses, all 36 footprint-report-
prose-v2 canary runs, and both example fixtures under V3 changed exactly
**5 scores**, all in the two target concepts, all recall gains of +1
quality point each, each corroborated as substantive by the frozen
manual audit. Zero non-target concept changes. Zero changes to any other
scoring field (decision, forbidden, receipt, counts). See
`v2-v3-diagnostic.json`, `change-report.json`, and `manual-audit.md`.
