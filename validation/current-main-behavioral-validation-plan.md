## Decision rules

- `VALIDATION_INFRASTRUCTURE_DEFECT`: a harness, identity, schema, blinding, budget, protocol, protection, leak, or required-routing gate fails. This takes precedence over behavioral interpretation.
- `MODEL_CREDITS_OR_RUNTIME_BLOCKED`: infrastructure is usable but the required model/runtime cannot complete valid calls. This takes precedence over inconclusive behavioral evidence.
- `OWNER_DECISION_REQUIRED`: Issue #1 cannot be resolved from evidence, no comparable baseline can be justified, or another explicit owner choice blocks the defined run.
- `CURRENT_MAIN_REGRESSION_FOUND`: the frozen valid run has any critical material loss, target-only dangerous failure, two or more noncritical material losses, or material negative-control false-positive growth.
- `CURRENT_MAIN_VALIDATION_INCONCLUSIVE`: the run is otherwise valid but required scenarios remain incomparable, a material judge inconsistency remains after the one adjudication, or evidence cannot support either regression or support.
- `CURRENT_MAIN_BEHAVIORALLY_SUPPORTED`: deterministic checks pass; all required families run validly; no material regression, target-only dangerous failure, unresolved material inconsistency, or material negative-control growth remains.
- Precedence is the order above, except `OWNER_DECISION_REQUIRED` applies before model execution when baseline or issue resolution is blocked. Deterministic cleanup completion never satisfies the behavioral-validation objective by itself. Never claim losslessness; use “no material regression detected in the tested scenarios” or “behaviorally supported within the tested scope.”
- Stop model-backed execution if credits/runtime, protected judging, baseline comparability, or infrastructure validity cannot support a truthful result; still complete safe deterministic cleanup and documentation under the applicable non-success category.
